3.2 Configure Hardware Parameters¶

Hardware uses the root config.yaml. Check at least the following settings.

Motor Communication¶

motor_communication:
  type: "spi"
  board: "rk3588"
  spi_device0: "/dev/spidev2.0"
  spi_device1: "/dev/spidev2.1"

board supports rk3588 or upboard and selects the corresponding SPI frame and conversion logic; it is not the same concept as the current CPU architecture. Device nodes must match the onsite system.

IMU¶

imu:
  type: "lord"
  port_base: "/dev/ttyUSB"
  port_number: 0

lord uses port_base + port_number; hipnuc uses the configured full serial-port path. Confirm device permissions and make sure the serial port is not occupied by another process.

Power and Clock Synchronization¶

  • power_reader controls power/BMS data reading. Check the CAN interface or matching device.
  • tsync_cdc controls the time-synchronization CDC serial port. The default device is /dev/ttyACM2.

If the corresponding hardware is not present onsite, explicitly disable the related feature according to the delivery configuration instead of repeatedly starting with an invalid device name.

Channels and Resources¶

development:
  robot_id: "Y20W"
  state_channel: "Y20W_development_state"
  command_channel: "Y20W_development_command"
gamepad:
  lcm_control_channel: "QUAD_ROBOT_CONTROL_Y20W"
  lcm_state_channel: "QUAD_ROBOT_STATE_Y20W"
safety_checker:
  urdf_path: "resources/robots/quad144w/urdf/sduog144_V2_s.urdf"

Policies and Control Period¶

Current key rl_walk parameters:

Field Current value Purpose
obs_dim 57 Policy observation dimension
dof_dim 16 Total wheel-leg DOF
joint_dim / wheel_dim 12 / 4 Main joint and supplement groups
control_dt 0.02 s Policy control period
decimation 10 Control downsampling
action_scale 0.25 Leg-joint action scale
action_scale_wheel 10 Wheel action scale
clip_obs / clip_action 100 / 100 Observation and action clipping
tau_limit 200 Configured torque limit

Model files, default 16D posture, Kp/Kd, scaling, and control period must be modified as a set. Replacing only the ONNX file can leave dimensions correct but semantics wrong.

Gamepad and Upper-Layer Control¶

Field Current value Notes
device_type hybrid Supports the hybrid input mode in the configuration
joystick_device /dev/input/js0 Linux gamepad device
deadzone 0.1 Joystick dead zone
Forward/backward/lateral limits 1.0 m/s Current configured speed limits
speed_yaw_max 1.3 rad/s Yaw-rate limit

For initial hardware tests, use a more conservative separate configuration. Calibrate the gamepad first, then verify mode buttons and zero positions, and only then open speed gradually.

Safety Checks¶

enable_safety_check is the master switch; each enable_*_check controls a specific check. The current configuration does not enable every check. Seeing the master switch set to true does not mean posture, joint position, velocity, torque, and hardware-loss protections are all active.

Configuration Current value Notes
enable_leg_cartesian_velocity_check true Leg Cartesian velocity check currently enabled
enable_orientation_check false Posture thresholds currently do not trigger protection
enable_joint_*_check false Joint position, velocity, and torque checks currently disabled
enable_hardware_loss_check false Hardware-loss protection currently disabled
safety_margin_factor 0.95 Safety margin factor for URDF limits
max_roll_deg / max_pitch_deg 30 / 50 Used when posture check is enabled

Before enabling or disabling any safety item, verify the trigger condition, state-machine result, and recovery method on a stand. Do not disable protection only to remove log messages.

Configuration Acceptance¶

test -e /dev/spidev2.0
test -e /dev/spidev2.1
test -e /dev/ttyUSB0
test -e /dev/ttyACM2
test -f resources/robots/quad144w/urdf/sduog144_V2_s.urdf

Device names are only for checking the current default configuration. Onsite systems should use the actual enumeration results. If optional hardware is missing, explicitly disable the corresponding reader and record the reason.
