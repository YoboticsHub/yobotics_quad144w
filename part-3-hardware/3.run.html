3.3 Start the Controller¶

Automatic Architecture Selection¶

run_robot_controller.sh selects the runtime directory according to uname -m:

System architecture Preferred entry Shared-library directory
x86_64 bin/ybt_ctrl lib/
aarch64 / arm64 bin_rk3588/ybt_ctrl lib_rk3588/

The script falls back to bin/ and lib/ only when the ARM directories do not exist. If a controller path is provided explicitly, the user-specified value takes precedence.

Startup Command¶

sudo bash scripts/run_robot_controller.sh --config config.yaml

The default LCM interface is eth0. If the onsite interface is different:

sudo bash scripts/run_robot_controller.sh --config config.yaml --iface <interface-name>

You can also use an environment variable:

LCM_IFACE=<interface-name> sudo -E bash scripts/run_robot_controller.sh --config config.yaml

The wrapper sets LD_LIBRARY_PATH; running ybt_ctrl.bin directly is not recommended.

Check Startup Output¶

Before executing the controller, the script prints the system architecture, deployment layout, executable, configuration file, library directory, and LCM interface. Confirm that these paths match the current device before continuing.

On ARM platforms, the script selects the RK3588 directories only when bin_rk3588/ or lib_rk3588/ exists; otherwise it falls back to generic bin/ and lib/. Fallback only describes path selection and does not prove the program is suitable for ARM.

Startup Success Indicators¶

  • Both SPI buses and the IMU open successfully.
  • The controller does not exit immediately or continuously print hardware errors.
  • High-level state and raw joint state update continuously.
  • Data, temperature, fault, and driver state are readable for all 16 joints.
  • In initial DAMP, the robot has no active motion.

Startup Failure¶

Symptom Check first
Controller not found Architecture printed by the script and bin* directories
Shared library not found Matching lib* directory and script entry
SPI permission or device error Device node, board type, and root permission
IMU cannot open Type, serial path, permissions, and occupying process
Local run works but remote has no state --iface, multicast URL, routing, and firewall

After startup, continue with State Checks and Stop. Do not switch motion modes directly.
