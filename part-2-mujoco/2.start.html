2.2 Start and Stop¶

Graphical Mode¶

conda activate quad_controller
bash scripts/start_mujoco.sh --config config_sim.yaml

Headless Mode¶

bash scripts/start_mujoco.sh --config config_sim.yaml --headless

Custom Controller Arguments¶

After start_mujoco.sh recognizes its own arguments, it passes the remaining arguments to the controller. View script options with:

bash scripts/start_mujoco.sh --help

The script checks simulation.enable_mujoco, the scene file, Python dependencies, and the controller entry, and automatically sets the shared-library path. x86_64 simulation uses bin/ybt_ctrl and lib/ by default.

Script Execution Order¶

start_mujoco.sh will:

  1. Parse the configuration path and headless option.
  2. Confirm MuJoCo is enabled in the configuration.
  3. Locate the scene, controller, and runtime libraries.
  4. Set PYTHONPATH, YBT_CONFIG_FILE, and LD_LIBRARY_PATH.
  5. Start MuJoCo in the background.
  6. Wait for simulation initialization, then start the controller in the foreground.
  7. Clean up both processes when it receives an exit signal.

Using the wrapper script lets the simulator and controller share the same configuration and environment. If you start them separately, you must keep these variables and the stop order consistent yourself.

Startup Success Indicators¶

  • The terminal clearly shows the configuration and scene being used.
  • Graphical mode shows the Y20W scene; headless mode has no DISPLAY error.
  • The controller keeps running instead of exiting immediately.
  • Joint state, command, and IMU channels appear continuously.
  • The model does not diverge rapidly in its initial state.

Normal Stop¶

Press Ctrl+C and wait for the script to clean up both processes. Do not run multiple simulations on the same LCM channels at the same time, or commands and states may interfere with each other.

If the next startup fails after stopping, first check for old controller or MuJoCo processes instead of changing channel names to bypass the problem.
