6.3 DataChannel 协议¶

publisher 创建名为 chat 的 DataChannel。客户端发送 JSON 字符串后，publisher 将其转换为 sport_client_cmd_t 并发布到 QUAD_ROBOT_CONTROL_Y20W；控制器状态再以 JSON 字符串回传。

控制 JSON¶

{
  "mode": 1002,
  "v": [0.2, 0.0, 0.0],
  "rpy": [0.0, 0.0, 0.0],
  "h": [0.0],
  "variable": [0, 0, 0]
}
字段 类型 转换结果 默认值
mode integer sport_client_cmd_t.api 0
v 3 个 number velocity[0:3] [0, 0, 0]
rpy 3 个 number euler_angles[0:3] [0, 0, 0]
h 至少 1 个 number body_height 使用第一项 [0]
variable 最多 3 个 integer variable[0:3]，不足补零 [0, 0, 0]

publisher 还固定设置：

rc_enable = 1
step_height = 0

常用模式编号与 SDK 一致：

模式 API
PASSIVE 1000
DAMP 1001
RL_WALK 1002
DEVELOPMENT 1005
RECOVERY_STAND 1006
STAND_DOWN 1007

当前转发层不做运动限幅

publisher.py 只把 JSON 转为数值，没有对速度、高度或姿态做 SDK/HTTP 那样的范围限制。客户端必须校验类型、数组长度、有限值和安全范围，并由控制器状态确认命令结果。

数组应提供完整长度。v 或 rpy 少于 3 项可能导致固定长度 LCM 字段编码失败；h 为空数组会导致索引错误。JSON 中的字符串数值虽然可能被 float() 接受，也不应作为正式协议使用。

状态 JSON¶

收到 QUAD_ROBOT_STATE_Y20W 后，publisher 回传：

{
  "code": 0,
  "power": [0.0, 0.0],
  "rpy": [0.0, 0.0, 0.0],
  "v": [0.0],
  "h": [0.0],
  "state": 0,
  "fault": 0,
  "env": [0.0, 0.0, 0.0]
}
字段 含义
code 当前固定为 0
power 高层状态的两个电源值
rpy roll、pitch、yaw，发送前保留两位小数
v 高层速度标量，以单元素数组表示
h 高度标量，以单元素数组表示
state 控制器状态编号
fault 高层故障码
env 三个环境状态值

该状态不包含 16 轴关节、温度或驱动故障。需要完整诊断时应同时使用 LCM Monitor 或 SDK 状态客户端。

客户端发送原则¶

  1. 连接后先发送 DAMP 和零速度。
  2. 读取状态确认控制器在线。
  3. 按合法状态机顺序进入站立和运动模式。
  4. 运动期间周期刷新命令，不依赖一次发送永久生效。
  5. 页面失焦、摇杆释放、DataChannel closing/closed 时立即发送零速度。
  6. 断开前切回 DAMP 并从状态确认。

校验示例¶

客户端发送前至少执行等价检查：

function validVector(value, length) {
  return Array.isArray(value) &&
    value.length === length &&
    value.every(Number.isFinite);
}

if (!Number.isInteger(command.mode) ||
    !validVector(command.v, 3) ||
    !validVector(command.rpy, 3) ||
    !validVector(command.h, 1)) {
  throw new Error("invalid Y20W control command");
}

还应根据应用设置保守范围和变化率限制。远程链路不能以“控制器可能会限幅”替代客户端校验。

验收¶

  • JSON 字段类型和长度固定；
  • 命令成功转换为 sport_client_cmd_t；
  • mode 与控制器状态变化对应；
  • 速度清零后状态和机器人响应恢复；
  • DataChannel 断开路径会触发客户端安全动作；
  • 故障状态在界面上醒目呈现，而不是仅记录日志。
