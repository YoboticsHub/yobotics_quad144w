6.3 DataChannel Protocol¶

The publisher creates a DataChannel named chat. After the client sends a JSON string, the publisher converts it to sport_client_cmd_t and publishes it to QUAD_ROBOT_CONTROL_Y20W; controller state is returned as a JSON string.

Control JSON¶

{
  "mode": 1002,
  "v": [0.2, 0.0, 0.0],
  "rpy": [0.0, 0.0, 0.0],
  "h": [0.0],
  "variable": [0, 0, 0]
}
Field Type Conversion result Default
mode integer sport_client_cmd_t.api 0
v 3 numbers velocity[0:3] [0, 0, 0]
rpy 3 numbers euler_angles[0:3] [0, 0, 0]
h at least 1 number first item is used as body_height [0]
variable up to 3 integers variable[0:3], zero-filled if short [0, 0, 0]

The publisher also sets:

rc_enable = 1
step_height = 0

Common mode numbers match the SDK:

Mode API
PASSIVE 1000
DAMP 1001
RL_WALK 1002
DEVELOPMENT 1005
RECOVERY_STAND 1006
STAND_DOWN 1007

The current forwarding layer does not limit motion

publisher.py only converts JSON into numeric values. It does not apply SDK/HTTP-style limits to velocity, height, or posture. The client must validate types, array lengths, finite values, and safe ranges, and confirm command results through controller state.

Arrays should be complete. v or rpy with fewer than 3 items may make fixed-length LCM field encoding fail; an empty h array causes an index error. String numeric values in JSON may be accepted by float(), but should not be used in the formal protocol.

State JSON¶

After receiving QUAD_ROBOT_STATE_Y20W, the publisher returns:

{
  "code": 0,
  "power": [0.0, 0.0],
  "rpy": [0.0, 0.0, 0.0],
  "v": [0.0],
  "h": [0.0],
  "state": 0,
  "fault": 0,
  "env": [0.0, 0.0, 0.0]
}
Field Meaning
code Currently fixed as 0
power Two high-level power values
rpy roll, pitch, yaw rounded to two decimals before sending
v High-level velocity scalar as a single-item array
h Height scalar as a single-item array
state Controller state number
fault High-level fault code
env Three environment-state values

This state does not contain 16-axis joints, temperature, or driver faults. Use LCM Monitor or the SDK state client for full diagnostics.

Client Sending Principles¶

  1. Send DAMP and zero velocity immediately after connection.
  2. Read state to confirm the controller is online.
  3. Enter standing and motion modes in a valid state-machine order.
  4. Periodically refresh commands during motion; do not rely on one send lasting forever.
  5. Send zero velocity immediately when the page loses focus, joystick is released, or DataChannel is closing/closed.
  6. Switch back to DAMP and confirm through state before disconnecting.

Validation Example¶

Before sending, the client should perform at least equivalent checks:

function validVector(value, length) {
  return Array.isArray(value) &&
    value.length === length &&
    value.every(Number.isFinite);
}

if (!Number.isInteger(command.mode) ||
    !validVector(command.v, 3) ||
    !validVector(command.rpy, 3) ||
    !validVector(command.h, 1)) {
  throw new Error("invalid Y20W control command");
}

Also apply conservative range and rate limits according to the application. A remote link must not replace client validation with “the controller may clamp it”.

Acceptance¶

  • JSON field types and lengths are fixed.
  • Commands are successfully converted to sport_client_cmd_t.
  • mode corresponds to controller state changes.
  • After zeroing velocity, state and robot response recover.
  • DataChannel disconnect paths trigger client safety actions.
  • Fault state is prominent in the UI rather than only logged.
