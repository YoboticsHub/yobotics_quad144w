1.1 Framework and Robot¶

quad144w/Y20W is a 16-DOF wheel-legged robot with four legs and four wheels. Each leg contains hip, thigh, calf, and wheel. The control framework provides reinforcement-learning motion modes, MuJoCo simulation, hardware control, an SDK, LCM external-algorithm integration, and WebRTC interfaces.

Gamepad / SDK / WebRTC
          |
          v
   Y20W controller state machine <---- DEVELOPMENT external algorithm
          |
     +----+----+
     |         |
  MuJoCo     SPI + IMU
 simulation  real robot

Control Modes¶

Mode Purpose
DAMP Damping and safe stop
RECOVERY_STAND Recover to standing
RL_WALK Normal wheel-legged locomotion
RL_HIGHSPEED High-speed policy
RL_CLIMB Climbing/obstacle policy
RL_STAND Reinforcement-learning standing policy
DEVELOPMENT External algorithm sends joint commands

The switchable mode order is defined by gamepad.mode_sequence in config.yaml or config_sim.yaml.

Data Layout¶

Algorithms use a 16D interleaved order:

LF: hip, thigh, calf, wheel
RF: hip, thigh, calf, wheel
LR: hip, thigh, calf, wheel
RR: hip, thigh, calf, wheel

For compatibility with lower-level interfaces, LCM messages split this into a 12D leg-joint array and a 4D supplement wheel-joint array. Development algorithms must not simply take the first 12 values from a 16D array.

Component Responsibilities¶

Component Responsible for Not responsible for
Controller State machine, policy execution, safety checks, low-level command output External algorithm model training or video transport
MuJoCo Simulation dynamics, virtual joints, and IMU data SPI, power, and real mechanical risk
SDK High-level mode/velocity commands and state reads Direct motor driving
External algorithm DEVELOPMENT state handling and joint target generation Bypassing the controller safety state machine
WebRTC Video and remote JSON forwarding Robot motion safety decisions

Recommended Mode Order¶

Normal validation starts from DAMP, enters RECOVERY_STAND to establish a stable posture, then moves to standing, low-speed walking, or DEVELOPMENT. High-speed and climbing policies must be validated separately in suitable venues.

Warning

gamepad.mode_sequence controls the switchable order in the field. This manual explains mode purposes; it does not mean any two modes can be switched directly.

Next Steps¶

  • First-time users should continue to System and Environment.
  • To validate policies, go to MuJoCo Simulation.
  • To develop joint-level algorithms, start with LCM and External Algorithms.
