1.1 框架与机器人¶

quad144w/Y20W 是四腿四轮的 16 自由度轮足机器人。每条腿包含 hip、thigh、calf 和 wheel，控制框架提供强化学习运动模式、MuJoCo 仿真、实机控制、SDK、LCM 外部算法和 WebRTC 接口。

遥控器 / SDK / WebRTC
          |
          v
   Y20W 控制器状态机 <---- DEVELOPMENT 外部算法
          |
     +----+----+
     |         |
  MuJoCo     SPI + IMU
   仿真       真实机器人

控制模式¶

模式 用途
DAMP 阻尼与安全停止
RECOVERY_STAND 恢复站立
RL_WALK 常规轮足运动
RL_HIGHSPEED 高速策略
RL_CLIMB 攀爬/越障策略
RL_STAND 强化学习站立策略
DEVELOPMENT 由外部算法下发关节命令

控制模式的可切换顺序由 config.yaml 或 config_sim.yaml 中的 gamepad.mode_sequence 决定。

数据布局¶

算法侧使用 16 维交错顺序：

LF: hip, thigh, calf, wheel
RF: hip, thigh, calf, wheel
LR: hip, thigh, calf, wheel
RR: hip, thigh, calf, wheel

LCM 消息为兼容底层接口，将其拆成 12 维腿关节数组和 4 维 supplement 轮关节数组。开发算法不能把 16 维数组简单截成前 12 项。

组件职责¶

组件 负责 不负责
控制器 状态机、策略执行、安全检查、底层命令输出 外部算法模型训练和视频传输
MuJoCo 仿真动力学、虚拟关节和 IMU 数据 SPI、供电和真实机械风险
SDK 高层模式/速度指令与状态读取 直接驱动电机
外部算法 DEVELOPMENT 状态处理与关节目标生成 绕过控制器安全状态机
WebRTC 视频和远程 JSON 转发 机器人运动安全决策

推荐模式顺序¶

正常验证从 DAMP 开始，经 RECOVERY_STAND 建立稳定姿态，再进入站立、低速行走或 DEVELOPMENT。高速和攀爬策略必须在对应场地单独验证。

Warning

gamepad.mode_sequence 决定现场可切换顺序。说明书列出模式用途，不代表任意两个模式之间都允许直接跳转。

下一步¶

  • 首次使用继续阅读 系统与环境。
  • 需要验证策略时进入 MuJoCo 仿真。
  • 开发关节级算法时先阅读 LCM 与外部算法。
