1.4 First Run¶

1. Check Package Integrity¶

test -x bin/ybt_ctrl
test -f config_sim.yaml
test -f resources_sim/robots/quad144w/scene_terrain.xml
test -f actor_model/y20w_v3/terrain/HumanActornet.onnx

On RK3588, replace the first item with bin_rk3588/ybt_ctrl.

2. Configure the Environment¶

bash scripts/setup_conda_env.sh
conda activate quad_controller

3. Start Simulation¶

bash scripts/start_mujoco.sh --config config_sim.yaml

On success, you should see the MuJoCo window, the controller entering its initial mode, and continuous joint/IMU LCM messages. Open another terminal to check:

bash scripts/monitor_lcm.sh --no-gui

4. Stop¶

Press Ctrl+C in the terminal that started the simulation. The script terminates the controller and MuJoCo child processes. After confirming there are no leftovers, modify configuration or start the next test.

Warning

The first run only validates simulation. Before hardware startup, you must still read Part 3 and check the emergency stop, stand, SPI, IMU, power, and safety parameters.

First-Run Success Indicators¶

  • The startup script reports no configuration, shared-library, or model path errors.
  • The MuJoCo scene contains only one Y20W and the initial posture is controllable.
  • Joint state, joint command, and IMU channels update continuously.
  • After Ctrl+C, the controller and simulation processes exit together.
  • Restarting does not report port conflicts, shared-resource conflicts, or duplicate processes.

If the First Run Fails¶

Symptom Check first
Missing Python module Whether quad_controller is activated and the actual python3 path
Scene not found XML path in config_sim.yaml and the current working directory
Shared library not found Whether startup used start_mujoco.sh
Window appears but robot does not move Controller log, LCM channels, and current mode
Window or process remains after stop Wait for script cleanup and confirm a second simulation is not running

After completing this page, follow Model and Mode Verification item by item. Do not jump directly to hardware.
