1.4 首次运行¶

1. 检查包完整性¶

test -x bin/ybt_ctrl
test -f config_sim.yaml
test -f resources_sim/robots/quad144w/scene_terrain.xml
test -f actor_model/y20w_v3/terrain/HumanActornet.onnx

在 RK3588 上将第一项换成 bin_rk3588/ybt_ctrl。

2. 配置环境¶

bash scripts/setup_conda_env.sh
conda activate quad_controller

3. 启动仿真¶

bash scripts/start_mujoco.sh --config config_sim.yaml

成功时应看到 MuJoCo 窗口、控制器进入初始模式，并持续产生关节/IMU LCM 消息。另开终端检查：

bash scripts/monitor_lcm.sh --no-gui

4. 停止¶

在启动仿真的终端按 Ctrl+C。脚本会终止控制器和 MuJoCo 子进程。确认没有残留后再修改配置或启动下一次测试。

Warning

首次运行只完成仿真验证。实机启动前还必须阅读第三部分并检查急停、支架、SPI、IMU、供电和安全参数。

首次运行成功标志¶

  • 启动脚本没有配置、动态库或模型路径错误；
  • MuJoCo 场景中只出现一台 Y20W，初始姿态可控；
  • 关节状态、关节命令和 IMU 通道持续更新；
  • Ctrl+C 后控制器与仿真进程一起退出；
  • 再次启动不会提示端口、共享资源或重复进程冲突。

首次失败时¶

现象 优先检查
Python 模块缺失 是否激活 quad_controller，以及 python3 的实际路径
找不到场景 config_sim.yaml 中 XML 路径和当前工作目录
找不到动态库 是否通过 start_mujoco.sh 启动
有窗口但机器人不动 控制器日志、LCM 通道和当前模式
停止后仍有窗口或进程 等待脚本清理，确认没有同时运行第二套仿真

完成本页后按 模型与模式验证逐项检查，不要直接跳到实机。
