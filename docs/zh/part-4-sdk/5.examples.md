# 4.5 仿真与实机使用

## 仿真联调

终端 1：

```bash
bash scripts/start_mujoco.sh --config config_sim.yaml
```

终端 2：

```bash
export YOBOTICS_LCM_URL='udpm://239.255.76.67:7667?ttl=255'
yobotics_sdk/build/yobot_robot_state_client
```

终端 3：

```bash
yobotics_sdk/build/yobot_sport_client
```

先确认状态读取正常，再从 `DAMP` 切换到站立和低速行走。

## 实机联调

1. 按第三部分启动控制器并确认机器人处于安全支撑状态。
2. SDK 主机和机器人配置同一 LCM 多播 URL。
3. 使用状态示例确认双向网络。
4. 启动运动示例，从 `DAMP` 和 `RECOVERY_STAND` 开始验证。

多网卡环境需要确保多播路由指向机器人所在网卡。可先运行 `bash scripts/monitor_lcm.sh --no-gui` 判断问题位于网络还是 SDK。

## 联调成功标志

1. 状态客户端先于运动客户端工作，并能看到持续更新。
2. SDK 发布后 `QUAD_ROBOT_CONTROL_Y20W` 出现。
3. 模式切换能在 `QUAD_ROBOT_STATE_Y20W` 中得到确认。
4. 小幅速度命令方向正确，清零后机器人停止。
5. 客户端退出前已发送零速度并切回安全模式。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| SDK 启动正常但无状态 | 比较 SDK 与控制器的 LCM URL，检查多播网卡 |
| 状态正常但模式不变 | 检查是否持续 `EnableLCMControl()`，以及其他输入源是否覆盖 |
| 模式变化但不运动 | 确认处于允许运动的模式、速度非零且无故障 |
| 松键后仍运动 | 确认业务循环主动发送零速度，不依赖进程退出 |
| 多个客户端互相覆盖 | 保留一个控制发布者，其余客户端只读状态 |
