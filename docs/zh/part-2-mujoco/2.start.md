# 2.2 启动与停止

## 图形模式

```bash
conda activate quad_controller
bash scripts/start_mujoco.sh --config config_sim.yaml
```

## 无图形模式

```bash
bash scripts/start_mujoco.sh --config config_sim.yaml --headless
```

## 自定义控制器参数

`start_mujoco.sh` 识别自身参数后，会把剩余参数传给控制器。查看脚本参数：

```bash
bash scripts/start_mujoco.sh --help
```

脚本会检查 `simulation.enable_mujoco`、场景文件、Python 依赖和控制器入口，并自动设置动态库路径。x86_64 仿真默认使用 `bin/ybt_ctrl` 与 `lib/`。

## 脚本执行顺序

`start_mujoco.sh` 会：

1. 解析配置路径和 headless 参数；
2. 确认配置中启用了 MuJoCo；
3. 查找场景、控制器和运行库；
4. 设置 `PYTHONPATH`、`YBT_CONFIG_FILE` 和 `LD_LIBRARY_PATH`；
5. 在后台启动 MuJoCo；
6. 等待仿真初始化后，在前台启动控制器；
7. 收到退出信号时清理两个进程。

使用包装脚本可以让仿真和控制器共享同一配置与环境。直接分别启动时，需自行保证这些变量和停止顺序一致。

## 启动成功标志

- 终端明确显示正在使用的配置和场景；
- 图形模式出现 Y20W 场景，headless 模式没有 DISPLAY 错误；
- 控制器继续运行而不是立即退出；
- 关节状态、命令和 IMU 通道持续出现；
- 初始状态下模型没有高速发散。

## 正常停止

按 `Ctrl+C`，等待脚本清理两个进程。不要在同一组 LCM 通道上同时启动多套仿真，否则命令与状态可能互相串扰。

停止后若再次启动出现异常，先检查是否还有旧的控制器或 MuJoCo 进程，而不是更改通道名绕过问题。
