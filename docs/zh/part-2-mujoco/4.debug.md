# 2.4 仿真调试

## LCM 监控

```bash
bash scripts/monitor_lcm.sh --no-gui
bash scripts/monitor_lcm.sh
bash scripts/launch_lcm_spy.sh
```

无终端消息时检查 `config_sim.yaml` 的通道名、LCM Python 模块和本机多播配置。

## 日志查看

仿真默认把控制器日志写入 `log/robot_log.txt`，RL CSV 路径由各策略块的 `log_file_path` 决定。

```bash
python3 scripts/data_viewer.py
python3 scripts/motor_trace_viewer.py log/motor_trace.csv
```

重点比较期望/实际关节位置、速度和扭矩，轮关节变量名称包含 `wheel`。

## 常见问题

| 现象 | 检查项 |
| --- | --- |
| 场景文件不存在 | `simulation.mujoco.xml_path` 是否指向 `resources_sim/` |
| 控制器找不到动态库 | 使用启动脚本，不要绕过包装入口直接运行 `.bin` |
| 模型加载失败 | actor/encoder 路径、ONNX Runtime 和模型输入输出维度 |
| 机器人突然发散 | 关节顺序、默认角、PD、action scale、控制周期 |
| 模式无法切换 | `gamepad.device_type`、输入设备与 `mode_sequence` |

## 调试闭环

1. 记录可复现的模式、速度命令和配置文件。
2. 用 LCM 监控确认输入、状态和输出通道是否连续。
3. 用日志 Viewer 比较期望值与实际值，定位到具体关节。
4. 回到 `DAMP`，一次只修改一个参数。
5. 重复相同操作并比较修改前后的日志。

## 现象到行动

| 现象 | 立即行动 | 下一步证据 |
| --- | --- | --- |
| 模型高速发散 | 切回安全模式并停止 | 发散前的关节目标、实际值和 PD |
| 某个 wheel 方向错误 | 停止 wheel 命令 | supplement 索引和 XML 轴向 |
| 状态频率正常但动作卡顿 | 检查命令频率 | 推理耗时、CPU 和发送循环 |
| 只有外部算法模式异常 | 改用 wave 低幅值复测 | 区分模型问题与 DEVELOPMENT 链路问题 |
| 所有模式均异常 | 检查底层状态与模型 | XML、关节顺序、控制周期和通道串扰 |

定位外部算法问题时继续阅读 [通信结构](../part-5-lcm-dev/1.structure.md)和 [ONNX 行走示例](../part-5-lcm-dev/5.walk-onnx.md)。
