# 6.2 配置与启动

## 依赖

```bash
python3 -m pip install websockets aiortc opencv-python numpy av
bash scripts/install_python_lcm.sh
```

验证当前解释器：

```bash
python3 -c "import websockets, aiortc, cv2, av, lcm; print('WebRTC dependencies OK')"
```

## 当前配置

`WebRTC_server/config.json` 默认使用本机 RTSP 流：

```json
{
  "use_camera": true,
  "camera": {
    "source_type": "rtsp",
    "device_index": 4,
    "rtsp_url": "rtsp://127.0.0.1:8554/back",
    "width": 640,
    "height": 360,
    "fps": 15
  },
  "lcm": {
    "url": "udpm://239.255.76.67:7667?ttl=255",
    "control_channel": "QUAD_ROBOT_CONTROL_Y20W",
    "state_channel": "QUAD_ROBOT_STATE_Y20W"
  },
  "signaling": {
    "server": "ws://localhost:8765"
  },
  "webrtc": {
    "low_latency": true,
    "max_fps": 15,
    "min_bitrate_kbps": 300,
    "start_bitrate_kbps": 500,
    "max_bitrate_kbps": 900
  }
}
```

## 视频源

| 配置 | 类型/当前值 | 说明 |
| --- | --- | --- |
| `use_camera` | bool / `true` | `false` 时使用生成的虚拟视频轨道 |
| `camera.source_type` | `usb` 或 `rtsp` | 当前为 `rtsp` |
| `camera.device_index` | int / `4` | USB 模式对应 `/dev/video4` |
| `camera.rtsp_url` | string | RTSP 模式地址，日志会隐藏其中的认证信息 |
| `width` / `height` | int | 请求的视频尺寸 |
| `fps` | int | 视频源目标帧率 |

USB 示例：

```json
"camera": {
  "source_type": "usb",
  "device_index": 0,
  "rtsp_url": "",
  "width": 640,
  "height": 360,
  "fps": 15
}
```

关闭真实视频可单独验证信令和 DataChannel：

```json
"use_camera": false
```

## 低延迟参数

| 字段 | 当前值 | 作用 |
| --- | ---: | --- |
| `low_latency` | `true` | 启用低延迟采集与编码设置 |
| `max_fps` | `15` | 限制最终视频帧率 |
| `min_bitrate_kbps` | `300` | 编码器最小目标码率 |
| `start_bitrate_kbps` | `500` | 初始目标码率 |
| `max_bitrate_kbps` | `900` | 编码器最大目标码率 |

代码会把摄像头帧率限制到 `max_fps`。码率参数会尝试写入视频编码参数，但实际效果仍取决于浏览器、编解码器和网络协商。

## LCM 与信令

- `lcm.url` 必须与控制器一致；
- 控制通道固定使用 `QUAD_ROBOT_CONTROL_Y20W`；
- 状态通道固定使用 `QUAD_ROBOT_STATE_Y20W`；
- publisher 默认连接本机 `ws://localhost:8765`；
- 远端客户端连接 `ws://<机器人可达IP>:8765`。

`localhost` 只适用于机器人内部 publisher 连接本机信令进程，不能作为远端客户端地址。

## 启动

推荐入口：

```bash
python3 WebRTC_server/control_publisher.py
```

当前入口按后台托管方式运行：自动管理信令和 publisher，没有旧版本的 `s`、`q`、`e` 键盘命令。使用 `Ctrl+C` 触发清理并退出。

启动顺序：

1. 信令服务监听 `0.0.0.0:8765`；
2. 管理进程等待外部客户端连接；
3. 外部连接写入就绪标记；
4. publisher 启动并注册角色；
5. publisher 发送 Offer，客户端返回 Answer；
6. ICE/PeerConnection 建立，视频和 DataChannel 开始工作。

## 成功标志

- `8765` 端口正在监听；
- 日志出现外部客户端和 publisher 注册；
- Offer/Answer 均被信令服务转发；
- PeerConnection 和 DataChannel 进入可用状态；
- 视频画面持续刷新；
- LCM 状态能够经 DataChannel 回传；
- 客户端命令出现在 `QUAD_ROBOT_CONTROL_Y20W`。

## 停止

按 `Ctrl+C` 停止管理进程，等待 publisher 和信令子进程退出。远程控制客户端应在断开前主动发送零速度并切回安全模式；WebRTC 断连本身不等于机器人命令已安全清零。
