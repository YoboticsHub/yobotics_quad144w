# 3.4 State Checks and Stop

## Checks After Startup

1. Both SPI devices opened successfully and no persistent driver errors are present.
2. IMU attitude is stable; angular velocity and acceleration are reasonable when stationary.
3. `QUAD_ROBOT_STATE_Y20W` and `Y20W_QUAD_JOINT_STATE` update continuously.
4. Position, velocity, fault, and temperature data are complete for all 16 joints.
5. Switching from `DAMP` to a standing mode is smooth and has no abnormal impact.

```bash
bash scripts/monitor_lcm.sh --no-gui
tail -f log/robot_log.txt
```

If the configuration uses an absolute log path, inspect that path instead of the project `log/` directory.

## Safe Stop

Prefer switching to `DAMP`, confirm the robot stops applying force, and then press `Ctrl+C` to stop the controller. If the robot loses control, communication is interrupted, or posture becomes abnormal, use the physical emergency stop immediately instead of waiting for software recovery.

## After an Exception

- Preserve controller logs and related CSV files.
- Record the mode, velocity command, and configuration version at the time of the issue.
- Check motor fault codes, temperature, SPI driver state, and IMU data.
- Do not re-enter the mode that caused the exception before the cause is confirmed.

## Checks Before Mode Switching

| Item | Continue if | Stop if |
| --- | --- | --- |
| Posture | Stationary and consistent with real direction | Jumping, wrong axis, or continuous drift |
| Joints | Complete 16D data and reasonable zero positions | Fixed abnormal values, mismatch, or rapid changes |
| Drivers | No faults and SPI status normal | Any fault or continuous frame loss |
| Temperature | Stable and differences between axes are reasonable | Fast rise or single-axis abnormality |
| Control input | Velocity and attitude targets are zero | Residual nonzero command exists |
| Safety equipment | Emergency stop available and stand reliable | Cannot stop immediately or support is unstable |

## Recovery Principles

After emergency stop or safety-check triggering, do not re-enable immediately. Save logs first, confirm the robot's mechanical state, then check power, drivers, IMU, joint zero positions, and the mode/command at trigger time. Resume testing only after the cause is clear and the related checks pass again.
