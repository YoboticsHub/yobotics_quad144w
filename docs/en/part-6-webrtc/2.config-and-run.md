# 6.2 Configuration and Startup

## Dependencies

```bash
python3 -m pip install websockets aiortc opencv-python numpy av
bash scripts/install_python_lcm.sh
```

Verify the current interpreter:

```bash
python3 -c "import websockets, aiortc, cv2, av, lcm; print('WebRTC dependencies OK')"
```

## Current Configuration

`WebRTC_server/config.json` uses a local RTSP stream by default:

```json
{
  "use_camera": true,
  "camera": {
    "source_type": "rtsp",
    "device_index": 4,
    "rtsp_url": "rtsp://127.0.0.1:8554/back",
    "width": 640,
    "height": 360,
    "fps": 15
  },
  "lcm": {
    "url": "udpm://239.255.76.67:7667?ttl=255",
    "control_channel": "QUAD_ROBOT_CONTROL_Y20W",
    "state_channel": "QUAD_ROBOT_STATE_Y20W"
  },
  "signaling": {
    "server": "ws://localhost:8765"
  },
  "webrtc": {
    "low_latency": true,
    "max_fps": 15,
    "min_bitrate_kbps": 300,
    "start_bitrate_kbps": 500,
    "max_bitrate_kbps": 900
  }
}
```

## Video Source

| Configuration | Type/current value | Description |
| --- | --- | --- |
| `use_camera` | bool / `true` | Uses generated virtual video when `false` |
| `camera.source_type` | `usb` or `rtsp` | Currently `rtsp` |
| `camera.device_index` | int / `4` | `/dev/video4` in USB mode |
| `camera.rtsp_url` | string | RTSP address; credentials are hidden in logs |
| `width` / `height` | int | Requested video size |
| `fps` | int | Target source frame rate |

USB example:

```json
"camera": {
  "source_type": "usb",
  "device_index": 0,
  "rtsp_url": "",
  "width": 640,
  "height": 360,
  "fps": 15
}
```

Disable real video to validate signaling and DataChannel separately:

```json
"use_camera": false
```

## Low-Latency Parameters

| Field | Current value | Purpose |
| --- | ---: | --- |
| `low_latency` | `true` | Enables low-latency capture and encoding settings |
| `max_fps` | `15` | Limits final video frame rate |
| `min_bitrate_kbps` | `300` | Encoder minimum target bitrate |
| `start_bitrate_kbps` | `500` | Initial target bitrate |
| `max_bitrate_kbps` | `900` | Encoder maximum target bitrate |

The code limits camera frame rate to `max_fps`. Bitrate parameters are applied to video encoding settings when possible, but the actual effect still depends on browser, codec, and network negotiation.

## LCM and Signaling

- `lcm.url` must match the controller.
- The control channel is fixed as `QUAD_ROBOT_CONTROL_Y20W`.
- The state channel is fixed as `QUAD_ROBOT_STATE_Y20W`.
- The publisher connects to local `ws://localhost:8765` by default.
- Remote clients connect to `ws://<robot-reachable-ip>:8765`.

`localhost` is only for the robot-internal publisher connecting to the local signaling process. It is not a valid remote-client address.

## Startup

Recommended entry:

```bash
python3 WebRTC_server/control_publisher.py
```

The current entry runs as a background manager: it automatically manages signaling and publisher processes and does not include old `s`, `q`, or `e` keyboard commands. Use `Ctrl+C` to clean up and exit.

Startup order:

1. Signaling service listens on `0.0.0.0:8765`.
2. Manager waits for external client connection.
3. External connection writes the ready marker.
4. Publisher starts and registers its role.
5. Publisher sends Offer, and client returns Answer.
6. ICE/PeerConnection is established, then video and DataChannel start working.

## Success Indicators

- Port `8765` is listening.
- Logs show external client and publisher registration.
- Offer and Answer are both forwarded by signaling.
- PeerConnection and DataChannel become available.
- Video refreshes continuously.
- LCM state is returned through DataChannel.
- Client commands appear on `QUAD_ROBOT_CONTROL_Y20W`.

## Stop

Press `Ctrl+C` to stop the manager and wait for publisher and signaling child processes to exit. The remote-control client should actively send zero velocity and switch back to a safe mode before disconnecting; a WebRTC disconnect itself does not mean robot commands have been safely zeroed.
