# 2.1 仿真结构

MuJoCo 进程加载 Y20W 场景并通过 LCM 与控制器交换关节和 IMU 数据。控制器使用与实机相同的状态机和策略配置，但电机通信类型改为 `lcm`。

```text
config_sim.yaml
      |
      +--> mujoco_sim.mujoco_simulator
      |       发布 Y20W_QUAD_JOINT_STATE / Y20W_QUAD_IMU_DATA
      |       订阅 Y20W_QUAD_JOINT_COMMAND
      |
      +--> bin/ybt_ctrl
              加载 actor_model/ 并运行状态机
```

仿真默认关键项：

```yaml
motor_communication:
  type: "lcm"
simulation:
  enable_mujoco: true
  mujoco:
    xml_path: "resources_sim/robots/quad144w/scene_terrain.xml"
```

仿真用于验证模型能否加载、16 维关节顺序、动作连续性、模式切换、LCM 通信和日志输出。它不能替代实机的 SPI、IMU、供电和机械安全检查。

## 一个控制周期

1. MuJoCo 根据上一帧执行器目标推进动力学。
2. 仿真发布 12+4 关节状态和虚拟 IMU。
3. 控制器更新状态估计、状态机和当前策略。
4. 控制器发布 12+4 关节命令。
5. MuJoCo 接收命令并进入下一步。

外部算法启用时，控制器还会生成 `Y20W_development_state`，并把 `Y20W_development_command` 作为 DEVELOPMENT 状态机输入。外部算法仍不直接连接 MuJoCo。

## 仿真能验证什么

| 可以验证 | 仍需实机验证 |
| --- | --- |
| 模型文件与维度 | SPI 帧与设备节点 |
| 关节名称、顺序和方向 | 电机零位、摩擦和机械装配 |
| 状态机与模式切换 | 真实 IMU 安装方向与漂移 |
| LCM 类型和通道 | 供电、BMS、时钟同步 |
| 观测、动作、缩放和 PD 趋势 | 温升、驱动故障和急停 |

仿真通过是上实机的必要条件，但不是实机安全结论。
