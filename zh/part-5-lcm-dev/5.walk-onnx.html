5.5 ONNX 行走示例¶

walk_algorithm 使用 encoder 和 actor 两个 ONNX 模型，把 Y20W 状态转换为 57 维观测，并输出 16 维轮足动作。该示例展示了完整策略推理链路，也要求模型训练约定与部署端完全一致。

执行链路¶

development_state_t
  -> 状态重排和缩放
  -> 57 维 observation
  -> HumanEncodernet.onnx + 循环状态
  -> latent
  -> HumanActornet.onnx + 循环状态
  -> 16 维 action
  -> 缩放 + 默认姿态
  -> q/qd/tau/Kp/Kd
  -> development_command_t (12+4)

encoder 必须有 3 个输入：观测、hidden、cell。actor 必须有 4 个输入：观测、latent、hidden、cell。代码从 ONNX session 读取实际输入名称和末维形状，并维护两组循环状态。

启动命令¶

python3 external_algorithms/walk_algorithm/run_algorithm.py \
  --config external_algorithms/walk_algorithm/config.yaml

相对模型路径以配置文件所在目录为基准，因此默认会加载：

external_algorithms/walk_algorithm/HumanEncodernet.onnx
external_algorithms/walk_algorithm/HumanActornet.onnx

启动前应先用 wave 完成通信和关节映射验证。这样 ONNX 异常和底层链路异常不会混在一起排查。

配置与优先级¶

策略配置¶

字段 默认值 说明
policy.type onnx 使用 ONNX Runtime
model_path ./HumanActornet.onnx actor 模型
encoder_path ./HumanEncodernet.onnx encoder 模型
read_metadata false 当前直接使用 YAML 中的模型参数
warmup_count 500 使用真实状态执行 500 次预热
action_threshold 100.0 预热动作绝对值检查阈值

模型参数¶

字段 默认值摘要 用途
num_obs 57 观测长度
num_actions 16 动作长度
default_joint_pos 每腿 [0, -0.8, 1.6, 0] 位置目标基准
joint_stiffness 腿 8，wheel 0 Kp
joint_damping 腿 0.2，wheel 0.5 Kd
action_scale 腿 0.25，wheel 10 动作到目标的逐轴缩放
dof_pos_scale 1.0 关节位置误差缩放
dof_vel_scale 0.05 关节速度缩放
ang_vel_scale 0.25 机身角速度缩放
command_scale 2.0 速度指令缩放
lin_vel_scale 2.0 配置中存在，但当前 57 维观测没有机身线速度项

当 read_metadata: false 时，YAML 是部署参数来源。设置为 true 且安装了 onnx 后，代码会从 actor metadata 读取 joint_names、默认位置、Kp、Kd、动作缩放、动作维度和观测维度，并覆盖对应内存参数。

Warning

当前 metadata 读取失败只打印警告，程序可能继续使用 YAML 参数。开启该功能后必须阅读启动日志，不能只依据配置文件判断最终参数。

57 维观测逐项说明¶

索引 长度 数据 处理
0:3 3 state.omega[0:3] 乘 ang_vel_scale
3:6 3 四元数计算的重力投影 不额外缩放
6:9 3 [v_des[0], v_des[1], omega_des[2]] 乘 command_scale
9:25 16 (dof_q - default_joint_pos) 乘 dof_pos_scale
25:41 16 dof_qd 乘 dof_vel_scale
41:57 16 上一帧 action_buffer 原值写入

总维度为 3 + 3 + 3 + 16 + 16 + 16 = 57。

角速度¶

角速度直接取 development_state_t.omega。训练和部署必须使用相同机体系、轴方向和单位。

重力投影¶

代码按四元数 [w, x, y, z] 计算机身坐标系中的重力方向。它向策略提供 roll/pitch 姿态信息，同时避免直接使用欧拉角的不连续性。

若上游四元数顺序是 [x, y, z, w]，计算仍能运行，但观测语义完全错误。替换状态来源时必须先做静止姿态和单轴倾斜测试。

速度命令¶

观测使用：

[前向速度 v_des[0], 横向速度 v_des[1], 偏航角速度 omega_des[2]]

v_des[2] 和 omega_des[0:2] 不进入当前策略观测。

关节位置与速度¶

LCM 的 12+4 状态重排为：

[LF_hip, LF_thigh, LF_calf, LF_wheel,
 RF_hip, RF_thigh, RF_calf, RF_wheel,
 LR_hip, LR_thigh, LR_calf, LR_wheel,
 RR_hip, RR_thigh, RR_calf, RR_wheel]

位置先减去 default_joint_pos，速度不减零位。两者分别乘各自缩放。

历史动作¶

action_buffer 初始化为全零。每次推理成功并通过有限值检查后，基类在锁保护下保存当前动作；下一次观测读取它作为最后 16 维输入。

观测裁剪¶

compute_observation() 使用 model_params.obs_clip_range，配置未提供时默认裁剪到 [-100, 100]。基类推理前也会对绝对值超过 100 的观测再次裁剪。

裁剪可以阻止数值爆炸，但持续触发裁剪通常意味着缩放、单位或传感器状态错误，应修复来源而不是依赖裁剪维持运行。

Encoder 与 Actor 推理¶

Encoder¶

  1. 读取三个输入的名称和末维；
  2. 将观测 reshape 为 (1, obs_dim)；
  3. 首次运行时把 hidden 和 cell 初始化为 (1, 1, hidden_dim) 的全零数组；
  4. 执行 encoder；
  5. 保存输出 latent、新 hidden 和新 cell。

Actor¶

  1. 读取四个输入：observation、latent、hidden、cell；
  2. 将观测和 latent reshape 为二维 batch；
  3. 初始化或复用 actor 的循环状态；
  4. 执行 actor；
  5. 第一个输出展平并转换为 float32 动作；
  6. 如果还有 hidden/cell 输出，则更新循环状态。

每次重新开始 DEVELOPMENT 时，encoder 和 actor 的循环状态都会清零。

16 维动作处理¶

process_action() 依次执行：

  1. 拒绝 None 或空动作；
  2. 检查 NaN/Inf；
  3. 异常时尝试读取当前 action_buffer；
  4. 检查 action_scale 与动作长度；
  5. 检查并补齐 default_joint_pos；
  6. 计算位置和速度目标；
  7. 检查结果有限且长度正好为 16；
  8. 读取 Kp、Kd；
  9. 更新最新命令缓存，由发送线程发布。

当前计算为：

q_des  = action * action_scale + default_joint_pos
qd_des = action * action_scale
tau_des = 0

其中 wheel 的 action_scale 默认是 10，腿关节默认是 0.25。这反映当前模型的部署约定，不能直接移植到输出语义不同的模型。

NaN 回退的边界

基类会在更新 action_buffer 前拒绝 NaN/Inf，因此 walk 中对上一动作的回退通常只能使用最近一次有效动作。持续保持旧动作未必安全，自研算法应增加动作新鲜度和连续失败处理。

模型预热¶

默认预热执行 500 次真实状态推理：

  1. 等待 Y20W_development_state；
  2. 构造 57 维观测；
  3. 运行 encoder 和 actor；
  4. 检查每个动作的绝对值是否超过 100；
  5. 打印进度和成功推理次数；
  6. 最终检测到动作异常时打印观测、动作和异常索引并退出。

预热期间需要控制器持续发布状态，但不应据此认为关节命令已经生效。预热通过只说明模型能够在当前状态上执行且未触发该动作阈值。

仿真验收流程¶

  1. 用 wave 验证 DEVELOPMENT 链路和 16 维顺序。
  2. 在不进入 DEVELOPMENT 的情况下启动 walk，观察模型加载和 500 次预热。
  3. 确认预热成功次数合理，没有动作阈值、NaN 或 shape 错误。
  4. 保持速度命令为零，进入 DEVELOPMENT，检查站立和切换连续性。
  5. 分别给出小幅前向、横向和偏航命令，一次只验证一个轴。
  6. 检查指令撤回到零后动作能恢复稳定。
  7. 运行较长时间，观察推理错误、频率下降、状态断流和姿态漂移。
  8. 验证 Ctrl+C、模式切换和控制器停止时的退出行为。

建议记录：状态与命令频率、推理耗时、观测最大绝对值、动作最大绝对值、姿态、16 维位置/速度、轮速和异常计数。

故障排查¶

现象 检查 原因 处理
找不到模型 配置路径与当前目录 相对路径解析位置错误 使用项目根目录命令或检查模型是否位于配置目录
onnxruntime 无法导入 Python 环境 依赖未安装在当前解释器 激活项目环境并检查 python3 -c 'import onnxruntime'
Encoder 输入数量错误 ONNX 输入列表 模型结构不是当前 3 输入约定 修改部署适配层或导出匹配模型
Actor 输入数量错误 ONNX 输入列表 模型结构不是当前 4 输入约定 不要只改配置维度，需适配推理代码
metadata 没有生效 read_metadata、onnx 包、启动日志 metadata 缺失或解析失败 核对日志并回到明确的 YAML 参数
预热成功次数为 0 状态通道和 robot_id 没收到真实状态 先修复通信，不进入 DEVELOPMENT
观测经常被裁剪 原始状态、单位、缩放 传感器异常或训练归一化不一致 打印分段观测并定位来源
输出出现 NaN/Inf 输入、循环状态和模型 模型数值不稳定 退出模式，保存触发帧并离线复现
机器人进入模式后抖动 默认姿态、PD、控制周期 零位或增益不匹配 切回 DAMP，在仿真降低增益重新验证
速度不跟随 v_des、omega_des 和 command_scale 上游命令没进入观测或缩放不匹配 监控状态字段与观测索引 6:9
wheel 与腿动作错位 16 维重排和 supplement 使用了前 12+后 4 的错误顺序 按 索引表逐项核对

成功标志¶

  • 两个模型加载成功，输入数量和形状符合代码预期；
  • 500 次预热完成且无最终动作越界；
  • 57 维观测各分段数值和训练约定一致；
  • 16 维动作重排、默认姿态和缩放全部核对；
  • 零命令和小幅单轴命令在仿真中可重复运行；
  • 异常退出后控制器能够回到安全模式。

满足这些条件后，再按 自定义算法与实机接入执行分阶段验证。
