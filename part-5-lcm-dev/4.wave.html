5.4 wave 规则示例¶

wave_algorithm 不加载 ONNX 模型，而是直接生成低频正弦关节偏移。它覆盖了状态接收、16 维排列、命令缓存、高频发送和安全退出，是理解 DEVELOPMENT 链路的首选示例。

适用场景¶

  • 第一次验证外部算法环境和 LCM 通道；
  • 检查 12+4 关节映射和四腿方向；
  • 验证 PD 参数与命令发送频率；
  • 为自定义规则算法建立最小工程模板。

它不是步态控制器。默认动作只让 thigh 与 calf 产生周期偏移，不提供平衡、落足规划或抗扰控制。

启动前提¶

  1. Python 能导入 numpy、yaml 和 lcm。
  2. MuJoCo 和控制器已经启动。
  3. Y20W_development_state 持续更新。
  4. 机器人处于可安全切换模式的状态。
  5. 实机测试时已经上支架并准备急停。

从项目根目录运行：

python3 external_algorithms/wave_algorithm/run_algorithm.py \
  --config external_algorithms/wave_algorithm/config.yaml

也可以在算法目录运行：

cd external_algorithms/wave_algorithm
python3 run_algorithm.py --config config.yaml

配置逐段说明¶

policy¶

字段 默认值 作用
type none 表示规则算法，不加载 actor 或 encoder
model_path 空 wave 不使用
encoder_path 空 wave 不使用
read_metadata false 没有模型 metadata
warmup_count 0 跳过 ONNX 预热
action_threshold 200.0 基类预热阈值；当前因不预热而不生效

RunAlgorithm._load_policy() 会把 model 和 encoder 设置为 None，并将策略类型标记为 none。

model_params¶

字段 默认值摘要 作用
num_actions 16 每腿 [hip, thigh, calf, wheel]
num_obs 57 为复用基类保留的观测缓冲区长度
default_joint_pos 每腿 [0, -0.8, 1.6, 0] 正弦偏移叠加前的基准姿态
joint_stiffness 腿关节 8，轮关节 0 位置增益 Kp
joint_damping 腿关节 0.2，轮关节 0.5 速度增益 Kd
action_scale 全部 1.0 当前 wave 实现不读取该字段进行二次缩放

Note

process_action() 直接执行 default_joint_pos + action。因此 wave 的幅值直接叠加到目标关节位置，action_scale 在当前实现中不参与计算。

lcm¶

字段 默认值 作用
url 空 使用默认 LCM 配置
state_channel Y20W_development_state 接收 DEVELOPMENT 状态
command_channel Y20W_development_command 发布 DEVELOPMENT 命令
robot_id Y20W 过滤状态并标记目标机器人

execution¶

字段 默认值 作用
frequency 100.0 Hz 正弦动作更新频率
lcm_send_frequency 200.0 Hz 最近命令的发送频率
auto_start true 收到匹配状态后在算法本地启动
auto_end true 达到最长时间时调用结束流程
max_execution_time 0.0 s 不按时间自动停止

motion¶

字段 默认值 作用
frequency 0.1 Hz 正弦运动频率，一次周期约 10 秒
amplitude 0.5 thigh 偏移峰值；calf 偏移峰值为其两倍且方向相反

其他配置¶

  • rl_mode.is_rl_mode: false 标识这是规则控制示例；
  • joint_mapping.enabled: false，当前示例按固定 Y20W 顺序工作；
  • debug.print_config: true，启动时打印最终配置；
  • debug.print_metadata: false，没有 ONNX metadata。

动作生成原理¶

运行时间为 t、频率为 f、幅值为 A 时：

phase        = 2 * pi * f * t
thigh_offset = A * sin(phase)
calf_offset  = -2 * A * sin(phase)

每条腿生成：

[hip, thigh, calf, wheel]
  = [0, thigh_offset, calf_offset, 0]

四条腿使用相同相位，因此主要表现为躯干同步上下变化：

  • hip 不增加横向摆动；
  • thigh 和 calf 反向变化，近似保持足端水平位置；
  • wheel 偏移保持零，避免把通信测试变成轮式运动测试。

process_action() 随后构造：

q_des   = default_joint_pos + action
qd_des  = 0
tau_des = 0
kp/kd   = model_params 中的数组

16 维交错数组由 LCMInterface 拆为 12 个腿关节和 4 个 wheel supplement。

状态和方法对应关系¶

方法 wave 中的作用
compute_observation() 将 12+4 位置、速度重组到观测前 32 维，并附带速度命令和四元数供调试
_run_inference() 忽略观测内容，根据时间生成 16 维正弦动作
process_action() 检查动作长度，叠加默认姿态并更新命令缓存
on_development_mode_start() 重置起始时间和步数，使正弦从新周期开始
on_development_mode_end() 把最新命令改为 enable_development_mode: false

compute_observation() 内部对字段读取使用异常捕获，字段异常时对应区域可能保持为零。它适合演示，不应被当作严格的状态完整性验证。

MuJoCo 验证流程¶

1. 启动仿真¶

bash scripts/start_mujoco.sh

确认模型稳定出现，控制器没有报告配置或模型加载错误。

2. 监控通道¶

bash scripts/monitor_lcm.sh --no-gui

先确认 Y20W_development_state，此时还不应依赖 wave 命令。

3. 启动 wave¶

python3 external_algorithms/wave_algorithm/run_algorithm.py \
  --config external_algorithms/wave_algorithm/config.yaml

成功日志应包括：配置路径、policy.type='none'、推理频率、发送频率和 DEVELOPMENT 启动提示。

4. 进入 DEVELOPMENT¶

使用当前手柄或上位机控制方式切换到 DEVELOPMENT。确认状态 mode 已变化，不要只看算法打印。

5. 检查动作¶

  • 四条腿方向一致；
  • hip 和 wheel 没有明显周期目标；
  • thigh 与 calf 方向相反；
  • 命令连续，无瞬时跳变；
  • 实际周期接近 motion.frequency；
  • Y20W_development_command 频率接近 200 Hz 的配置量级。

6. 退出¶

先切回 DAMP，再按 Ctrl+C 停止算法。确认命令中的 enable_development_mode 变为 0，机器人没有留在 DEVELOPMENT。

保守调参¶

实机首次测试不要直接沿用仿真幅值。建议使用一份单独配置副本，按以下顺序调整：

  1. 保持低频，只减小 amplitude；
  2. 验证四腿方向和零位；
  3. 在幅值固定后再调整 frequency；
  4. 最后根据响应检查 Kp、Kd；
  5. 每次只改一组参数并记录结果。

calf_offset 是 -2 * amplitude，因此 calf 的最大偏移大于 thigh。判断安全幅值时应按 calf 峰值计算，而不是只看配置中的 amplitude。

故障排查¶

现象 检查 可能原因 处理
算法启动后一直无动作 状态通道、robot_id、控制模式 没收到状态或未进入 DEVELOPMENT 逐级核对 模式生命周期
只有部分腿动作 16 维顺序和 12+4 消息 数组长度、腿顺序或生成类型错误 用低幅值逐腿核对索引
四腿方向与预期不同 URDF/XML 轴向和默认姿态 关节符号约定不同 先在仿真单关节验证，不直接改大幅值
高频振动 Kp/Kd、频率、状态延迟 增益过高或链路抖动 立即退出，减小增益与幅值后重新验证
切换瞬间跳变 当前姿态与 default_joint_pos 目标从实际位置突然跳到默认姿态 进入前对齐姿态，或在自定义算法中加入插值
wheel 意外转动 supplement 顺序、轮关节目标 16 维被当作前 12+后 4 检查每腿交错映射和 supplement
Ctrl+C 后仍在 DEVELOPMENT 控制器状态和禁用命令 进程被强制终止或状态机未切回 使用安全控制入口切回 DAMP，确认后再断开

通过标准¶

  • wave 连续运行多个周期，没有 NaN、异常日志或频率长时间下降；
  • 四条腿关节方向、wheel supplement 和默认姿态全部正确；
  • 从进入到退出 DEVELOPMENT 的状态变化可重复；
  • 算法退出后机器人处于安全模式；
  • 只有满足以上条件，才继续验证 ONNX 行走示例。
